# Локальний DNS (майбутнє)

Наразі MVP використовує файл `hosts` для резолвінгу доменів. Це простий, але незручний підхід:

- Кожен новий домен потребує окремого запису в hosts.
- `hosts` не підтримує wildcard.
- Потрібні права адміністратора для редагування.
- Потрібно оновлювати на кожному клієнтському ПК.

У майбутньому планується перехід на локальний DNS-сервер.

## Варіанти

### DNS на роутері
- Більшість роутерів підтримують локальний DNS.
- Wildcard-записи залежать від моделі.
- Один запис `*.home.arpa` → IP центрального сервера.

### AdGuard Home
- Встановлюється як Docker-контейнер.
- Підтримує wildcard-правила.
- Фільтрація реклами + DNS.
- Не додається в базовий compose.yaml — це окремий проєкт.

### Pi-hole
- Аналогічно AdGuard Home.
- Підтримує wildcard DNS.
- Потребує окремого налаштування.

### Власний DNS-сервер
- Наприклад, CoreDNS або Dnsmasq.
- Максимальна гнучкість.
- Вимагає досвіду в адмініструванні DNS.

## Приклад правила

Для AdGuard Home або Pi-hole правило виглядає так:
```
*.home.arpa 192.168.1.100
```

Після налаштування DNS `hosts` більше не потрібен.
