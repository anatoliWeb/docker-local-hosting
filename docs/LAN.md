# Доступ з інших комп'ютерів у локальній мережі

Цей документ описує, як відкрити сайти (`demo.home.arpa`, `traefik.home.arpa`) з іншого комп'ютера в тій самій локальній мережі.

## Вимоги

- Центральний комп'ютер з docker-local-hosting має постійну локальну IP-адресу (статичну або DHCP reservation).
- Порти 80 та 443 доступні з мережі.
- Клієнтський комп'ютер має доступ до центрального комп'ютера.

## Крок 1: Додати записи hosts на клієнтському ПК

### Windows
Відредагуйте `C:\Windows\System32\drivers\etc\hosts` з правами адміністратора:
```
192.168.1.100 demo.home.arpa
192.168.1.100 traefik.home.arpa
```

### Linux / macOS
Відредагуйте `/etc/hosts` з правами root:
```
192.168.1.100 demo.home.arpa
192.168.1.100 traefik.home.arpa
```

## Крок 2: Копіювання CA-сертифіката

Щоб браузер довіряв HTTPS-сертифікату, потрібно встановити локальний CA-сертифікат на клієнтському ПК.

Знайдіть CA-сертифікат на центральному комп'ютері:
```powershell
mkcert -CAROOT
```

Скопіюйте файл `rootCA.pem` (НЕ `rootCA-key.pem`) на клієнтський ПК.

### Windows (клієнт)
1. Двічі клацніть `rootCA.pem`
2. Натисніть "Встановити сертифікат"
3. Виберіть "Локальний комп'ютер"
4. Виберіть "Усі сертифікати в такому сховищі"
5. Виберіть "Довірені кореневі центри сертифікації"

### Linux (клієнт)
```bash
sudo cp rootCA.pem /usr/local/share/ca-certificates/
sudo update-ca-certificates
```

### macOS (клієнт)
```bash
sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain rootCA.pem
```

## Важливо

- НЕ копіюйте `rootCA-key.pem` на клієнтські ПК — це приватний ключ CA.
- Копіюйте лише `rootCA.pem` (сертифікат CA).

## Перевірка

### Через браузер
Відкрийте `https://demo.home.arpa` — повинен показати зелений замок.

### Через curl
```powershell
curl -I https://demo.home.arpa
```

## Windows Firewall

Якщо клієнт не може підключитися, на центральному комп'ютері:
1. Відкрийте `Windows Firewall with Advanced Security`
2. Переконайтеся, що є дозвіл для портів 80 та 443
3. Обмежте доступ лише для Private профілю

## Типові проблеми

### VPN
VPN може змінювати маршрутизацію. Тимчасово вимкніть VPN для перевірки.

### Інша підмережа
Якщо комп'ютери в різних підмережах, налаштуйте маршрутизацію на роутері.

### Firewall сторонніх антивірусів
Деякі антивіруси блокують вхідні з'єднання. Додайте винятки для портів 80/443.
